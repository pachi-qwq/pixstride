# Stage C：超大 PNG 路径

Stage A、Stage B 已合并。Stage C 正在本地开发；缓存和渲染器验收通过前，不宣称查看器已支持超大图片。
本轮尚未解码私人 48000 × 32000 PNG。

## C1 行解码原型

`large::stream` 用 `png 0.18.1` 逐行读取非隔行静态 PNG，将 RGB、调色板和灰度输入展开为 8-bit 通道，再把借用的行
转换成预乘 BGRA8，不分配完整位图。初始路径不支持 Adam7、APNG、16-bit 通道、ICC 和 HDR。
CPU 转换对编码值四舍五入，不做线性光颜色处理。

解码器有 64 MiB 尽力限制，调用方另设 4 MiB 行限制。块头预检使用检查过的 64 位偏移，限制单个附加块 1 MiB、合计
8 MiB，并限制块数。PNG 解码验证 CRC 和 Adler 校验，不解释忽略的文本和 ICC 内容。取消在块头与行之间检查，无法抢占
已经阻塞的文件系统读取。这些限制不能证明进程所有分配都有硬上限。

生成的小型 RGBA 图片逐行结果与 WIC 对比，预乘舍入差异不超过一个通道值。CRC 损坏、截断、超量元数据、取消和算术
限制测试通过。显式 Release 诊断分别用独立进程扫描生成的 8192 × 256、8192 × 8192 PNG：两者输入与输出行容量均为
65,536 字节，峰值工作集均为 10,022,912 字节；扫描分别耗时 13.698 ms、422.538 ms。这只验证高度增加 32 倍的样本，
不覆盖所有 PNG 编码和异常输入分配模式，没有读取私人极限图片。

## C2 磁盘金字塔

一次行扫描构建所有向上取整减半的层，直到 1 × 1。2 × 2 Box Filter 平均预乘的编码通道，奇数边缘重复取样。
内存只保留行，不保留完整层。Tile 带一像素邻接边框；测试用独立小图参考校验所有层，并检查第零层全部边框和不满整块的边缘。

暂选 1024，仍属实验配置。生成的 2049 × 1537 RGBA 在 Release 单次运行得到：

| 边长 | Tile 数 | 数据字节 | 构建 ms | 热缓存重开 ms | 逆序读 Tile ms |
| --- | --- | --- | --- | --- | --- |
| 512 | 38 | 16,986,000 | 386.591 | 0.328 | 4.173 |
| 1024 | 19 | 16,910,888 | 436.699 | 0.342 | 3.955 |
| 2048 | 14 | 16,875,968 | 513.083 | 0.311 | 3.738 |

这是文件系统热缓存下的单次样本，不是百分位或 GPU 上传测量。保守自有缓冲估算分别为 1,189,994 / 4,343,154 /
12,752,050 字节，不含解码器分配。1024 样本 Tile 经 PNG 压缩从 4,210,704 降至 1,192,620 字节，但增加编码
135.821 ms、解码 4.321 ms。初版使用原始 PBGRA8 缓存，以磁盘空间换取简单、有界的读取。

`pixels.bin` 保存带边框的 Tile；`index.bin` 保存格式版本、尺寸、源身份、由检查过的几何推导的层级、64 位偏移与长度、
Tile CRC32，索引另有 CRC。读取前验证长度和几何，读取每块时再验证其 CRC。默认磁盘总预算 2 GiB，Builder 预算
128 MiB（含解码器额度），磁盘另留 1 GiB 空间。这些估算不是进程内存的硬上限。

根目录文件 lease 串行化构建、打开与清理。活动读句柄阻止淘汰。完成的数据和索引同步到磁盘，再通过同卷目录重命名发布；
取消会清理半成品。后续构建清理可识别的遗留半成品。无效索引会重建；Tile CRC 错误会报错，需清理该缓存后重建。
构建需要空间时按最旧顺序淘汰已发布缓存，没有引入 LRU 数据库。其他进程正在构建同一根目录时返回忙错误，不做无界等待。

源验证比较规范路径、长度、修改时间及首、中、尾各 64 KiB 的 CRC32。构建期间只读句柄拒绝源文件写入和删除，发布前复查
身份。若变化不在抽样范围内且元数据未变，仍可能漏检；CRC32 也不是密码学内容身份。版本变化、抽样内容变化、活动缓存保护、
损坏、溢出和构建中断测试已通过。

私人原图目前只查过文件属性。负责人已批准 C3 通过后进行独立 10 GiB 缓存实验，1024 金字塔预计 8,224,561,220 字节。
在此检查点尚未读取原图像素。

```powershell
cargo test --release --locked release_tile_sizes_probe -- --ignored --nocapture
```

## 依赖与依据

`png 0.18.1` 和 `crc32fast 1.5.2` 均采用 MIT OR Apache-2.0。纯 Rust 解码无需部署独立 libpng DLL，且提供逐行 API；
普通 WIC 路径不承诺有界流式读取。image-rs 仓库持续发布变更，并说明有模糊测试；这不等于对 Pixstride 做过安全审计。
没有启用 nightly 特性或使用外部 AI 服务。

参见 [Reader API](https://docs.rs/png/0.18.1/png/struct.Reader.html)、
[Decoder 限制](https://docs.rs/png/0.18.1/png/struct.Decoder.html)和
[维护仓库](https://github.com/image-rs/image-png)。

将 `PIXSTRIDE_TEST_ROOT` 设为仓库外目录后运行显式内存诊断：

```powershell
cargo test --release --locked release_streaming_memory_probe -- --ignored --nocapture
```

C2 必须先验证有界磁盘金字塔，再做 C3 集成。C4 还要检查原图驻留状态、可用空间；首次生成超过 2 GiB 临时缓存前，
必须得到负责人明确批准。
